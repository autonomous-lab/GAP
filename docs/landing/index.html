What GAP does

Agent-to-agent commerce needs more than a message format. GAP specifies the full lifecycle — from identity to settlement — and ships a working node you can run today.

Discovery

Self-certifying DIDs (did:gap:), capability announcements, and well-known AgentCard endpoints — agents find each other without a registry monopoly.

Contracts & escrow

Ed25519-signed contracts with a real state machine. Payments park in escrow — off-chain reference or on-chain GapEscrow.sol — and release only on verified acceptance or arbitration.

Execution

Workflow composition (DAG), proof bundles, delivery and acceptance with hash-linked receipts. Every event lands on a tamper-evident audit spine.

Governance

Layered policy engine, delegation with budgets, sybil-resistant reputation, compliance gates, and a two-layer token model (stablecoin settlement + native incentives).

Security is not a slide

The reference implementation went through a formal audit — 19 findings (2 critical, 3 high) — and every actionable finding was fixed with a regression test.

On-chain escrow

Funds are held by the GapEscrow.sol contract, not by any node. park / release / refund / dispute / rule with checks-effects-interactions — no admin key, no rug pull. A relayer signs and submits EVM transactions; the node is never custodian.

Tamper-evident spine

Every receipt is hash-chained (RFC-0003) and anchored; redaction re-links the chain and is itself an auditable event. GDPR portability and integrity don't fight each other.

Crypto done right

Ed25519 with strict verification, 256-bit CSPRNG bearer tokens, 128-bit identifiers, persisted node identity (GAP_NODE_SEED). No floating-point money: amounts are exact minor units, matching the on-chain scale.

Hardened API

Per-token and per-IP rate limiting, fully parameterized SQL (regression-tested against injection), authenticated audit endpoints, generic error responses — and a test suite that exercises every route over real HTTP.

Architecture

An event-sourced node with a materialized state — SQLite for development, ClickHouse for production scale — deployed with Docker and horizontally scalable.

Storage spine

Event sourcing with a Storage trait and a cross-backend conformance suite. ClickHouse in production (system logs disabled — they grow forever), SQLite for dev and tests.

Deployment

Multi-stage musl Docker image, docker-compose for the stack, HAProxy load balancer + 3 nodes for scaling (docker-compose.scale.yml).

Performance

Worker-pool HTTP server with a minimal critical section. Throughput is stable under load — the two O(n²) hot paths found by benchmarking were eliminated (+17× to +373×).

Interop

RFCs cover delegation, workflow composition, credentials, compliance, sybil resistance, subscriptions, cooling-off, discovery, conformance levels and SLA reporting — all implemented.
